# Project Edith architecture

Edith is a local, single-user memory package integrated through an adapter. SQLite at `data/edith.db` is the source of truth. A future FAISS index at `data/edith.faiss` is derived from SQLite embeddings. The package does not import Jarvis or smolagents; only `edith/integration/jarvis_adapter.py` will connect application code to it.

Phase 1 provides configuration, typed input records, ordered SQLite migrations, a write-coordinating repository, episodic and semantic persistence services, conversation/message persistence, pending confirmation/question tables, and a common-secret scanner. Short-term context includes bounded recent turns and a rolling summary updated after extraction batches; assistant statements are explicitly excluded as user facts. Phase 2 adds a lazy `sentence-transformers/all-MiniLM-L6-v2` embedder and exact `IndexIDMap2(IndexFlatIP(384))` search behind `Embedder` and `VectorStore` interfaces. Phase 4 adds JSON-validated extraction with a cheap pre-filter, an injected `LiteLLMModel` client, sensitive-category confirmation, and a single background queue with retry, catch-up, idle, batch, end-of-conversation, and shutdown-flush handling.

Each repository instance uses a SQLite connection local to each thread. SQLite runs in WAL mode with `busy_timeout` and `secure_delete` enabled. Repository writes are serialized by an in-process reentrant lock. Hard deletion removes entity links and the memory row in SQLite, writes only a content-free event, commits, and requests a truncating WAL checkpoint. FAISS writes and saves use a store lock, and reads use the same lock for snapshot safety. Vector BLOBs and `index_status='pending'` are committed before FAISS changes; the row is marked indexed only after an atomic index save. Reconciliation removes orphan IDs and rebuilds from stored vectors, re-embedding only when missing or when the model changes.

Exact and cosine near-duplicates are reinforced in place. Single-valued semantic predicates can use an injected Pydantic-validated adjudicator; high-confidence updates supersede the old row and preserve its content and validity interval, while contradictions remain active and raise a pending question that can be resolved by an explicit choice. Consolidation is recorded in `consolidation_runs`; it merges near-duplicate semantic rows, creates an episodic summary with source IDs linked through `consolidated_into`, and archives rather than deletes source events. It flags stale semantic facts for review, queues recurring-theme candidates for explicit confirmation, recomputes importance using age and access, and supports restoring archived sources with `MemoryConsolidator.unarchive()`.

The smolagents adapter exposes save/search/update/delete, profile, recent events, project context, paginated listing, and queued consolidation tools. The opt-in Memory Inspector tab is added only when Edith is enabled and initialized; it supports filtered browsing, supersede history, corrections, hard deletion, fresh JSON export, integrity/rebuild, consolidation, stale-fact review flags, and optional `VACUUM`. With Edith disabled, the original chat layout is built directly without an extra tab.

The Gradio chat currently stores display messages in `gr.State` but sends each new prompt as an individual task. The adapter will use a delimited task prefix for retrieved context. Memory errors must fail open at that boundary.

When `EDITH_ENABLED` is true, Jarvis creates an app-launch conversation, appends retrieved context to the internal task while leaving the visible user message unchanged, and installs the `save_memory` and `search_memory` tools. The system prompt then marks memory as untrusted data and prohibits invented history. Memory retrieval failures log only the exception type and leave the original task intact. The explicit save tool rejects secret-like strings and holds detected sensitive-category candidates in `pending_confirmations` instead of inserting them into `memories`.

Each user message is persisted with secret-like tokens redacted before model generation; the assistant turn is persisted after the response. This preserves an in-flight user message for shutdown flush. Extraction sees user messages only and ignores acknowledgements, generic questions, and command-only turns before making an LLM request. LLM responses use temperature zero and Pydantic validation; malformed output receives one repair attempt, then the batch is permanently skipped and marked extracted. Provider failures retry with bounded exponential backoff and leave messages unextracted after retry exhaustion for startup catch-up. Sensitive candidates remain in `pending_confirmations` until an explicit yes/no or four-turn expiry; candidate JSON is cleared on resolution or expiry.

The extraction pre-filter will skip empty/very short acknowledgements, generic requests with no user-specific details, and command-like turns. It will retain batches containing first-person facts, preferences, plans, decisions, events, or explicit corrections. Extraction runs asynchronously and does not block the response.

Encryption at rest is intentionally out of scope and remains future work.
